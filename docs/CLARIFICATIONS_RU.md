# Уточнения к ТЗ — единые правила набора v1.1
Дата: 20.11.2026. Все сведения, номера, SMS, тарифы и координаты замеров синтетические. Это учебный оператор INAI Mobile, не действующие предложения операторов. Внешние сети, реальные SMS и платежи не нужны.
Эти уточнения необходимо выдать участникам до старта. Они дополняют исходный DOCX; при изменении правил жюри пересчитывает эталоны и сообщает всем командам.

## 1. SMS
UTF-8 CSV, стандартное экранирование, поля id,text,label; label ∈ {fraud,ok}. Скрытый файл содержит только id,text. high означает fraud, low и medium означают ok. Нормы риска из ТЗ сохраняются. Основной скрытый набор — 80 SMS, ровно 16 (20%) с обфускацией. Отдельный набор 50 — подмножество этих 80 для совместимости с первой формулировкой ТЗ; не считать его вторым независимым испытанием. Метка fraud означает мошенническое побуждение, а не просто наличие слова «банк» или ссылки. Официальные домены для учебной проверки: beeline.kg, balance.kg, nbkr.kg, mbank.kg; их поддомены разрешены, похожие суффиксы не разрешены. Все остальные ссылки используют зарезервированный .example, их не открывают.

## 2. Тарифы
CSV сохраняет три обязательных поля date,type,amount, дополнительно duration_sec,roaming. date — локальное время Asia/Bishkek в ISO 8601 без смещения. call.amount — секунды, data.amount — ГБ (1 ГБ = 1024 МБ), sms.amount — целое количество SMS. duration_sec — длительность data-сессии; для call/sms 0. roaming = 0/1, отсутствующее значение означает 0. Для звонков ceil(amount/60) применяется к каждой записи отдельно; нулевой звонок стоит 0. Все события в наборе остаются в пределах месяца.
Ночь [01:00:00,07:00:00): трафик сессии равномерно распределён по времени. Для тарифа с ночным безлимитом из расхода исключается только пересечение с ночью. Сессия с duration_sec=0 учитывается целиком по моменту date. Роуминг никогда не входит ни в пакеты, ни в ночной безлимит: цена за округлённую минуту, ГБ или SMS берётся из roaming_rates. Абонплата списывается и в месяце без потребления.
subscribers.json задаёт текущий тариф и ровно три месяца расчёта (в том числе пустые). Доппакеты действуют месяц, могут дублироваться, всего 0–2, одна выбранная комбинация применяется ко всем трём месяцам. Текущая стоимость — текущий тариф без доппакетов. Для нового тарифа средняя месячная экономия * 3 должна быть СТРОГО больше 50 сом. На том же тарифе смены нет, подключение пакетов бесплатно, достаточно положительной экономии. Если лучшая другая комбинация не окупается, проверяются следующие по стоимости допустимые комбинации; если подходящих нет — stay. При равенстве стоимости: остаться при нулевой экономии, затем меньше доппакетов, затем tariff_id и отсортированный список addon_id лексикографически. Деньги считаются без промежуточного округления; итоги до 0.01 сома ROUND_HALF_UP. Средние — за три месяца. monthly_savings не вычитает разовый переход; net_savings_3m его учитывает.

## 3. USSD
Открытые subscribers.json и packages.json — входные фикстуры, формат одинаков на скрытых данных. Баланс/комиссия — до 0.01 сома; комиссия ROUND_HALF_UP, получателю зачисляется сама сумма. Суточный лимит считается по успешно переведённой основной сумме, без комиссии, по местной дате Asia/Bishkek. Отмена и отказ не расходуют лимит. Начальный запрос перевода проверяет формат, диапазон суммы, существование получателя и запрет перевода себе; баланс и суточный лимит проверяются на шаге подтверждения. Подтверждение не резервирует деньги: все условия повторно проверяются атомарно в момент подтверждения. Таймаут сессии наступает при elapsed >= 30 s. Повторное подтверждение не выполняет операцию ещё раз. Номер ровно 12 цифр с 996, в том числе у получателя. Суммы перевода допускают до двух знаков после точки, пределы включительно.
Дерево *111#: 1 Интернет → 1 D1 (1 ГБ/30 сом), 2 D5 (5 ГБ/100 сом); 2 Минуты → 1 M50 (50 минут/40 сом); 0 назад на каждом вложенном уровне. После выбора пакета: 1 подтвердить / 2 отмена. Успех или отмена завершают сессию, 0 на первом уровне завершает её. Неверный пункт возвращает ошибку и end=false, оставляет меню прежним и обновляет таймаут. *100# и *102# одношаговые, end=true. Для неизвестного номера — ошибка, end=true. session_id привязан к msisdn: использование чужого ID не меняет его сессию. Тексты свободные, смысл и числа проверяются жюри. Запрос GET /log/{msisdn} показывает операции этого абонента, включая входящие переводы. Для записи в лог укажите тип, время, статус, сумму и контрагента, если он есть; конкретные имена полей свободны.

## 4. Детализация
UTF-8 CSV, datetime: YYYY-MM-DD HH:MM:SS или DD.MM.YYYY HH:MM:SS; суммы — точка/запятая, csv-кавычки обязательны для запятой. Пустая физическая строка тоже dropped_rows. Неверное число колонок, неизвестный type, неразбираемая дата, отрицательное/нечисловое/NaN/Infinity значение duration_sec,mb,cost_som — пропустить всю строку. number может быть пустым у data. Полные дубли не удалять при суммировании: это два списания и основание для аномалии.
Дневной z-score: расходы текущего календарного дня относительно семи ПРЕДЫДУЩИХ полных календарных дней; учитывать дни с нулевыми расходами; population std (ddof=0). Первые 7 дней не проверять. При std=0 и росте расходов z=+inf, иначе 0. Аномалия только z>3; datetime — 00:00:00 соответствующего дня, type=day_spike, возможная переплата = расходы дня минус среднее семи дней.
Ночная аномалия: платные sms/content в [00:00,06:00), переплата=полная стоимость. Новая подписка: первая в файле subscription на короткий цифровой номер длиной 3–6, переплата=полная стоимость. Дубль: совпадают type,number,duration_sec,mb,cost_som, datetime отличается на 0–60 s включительно; флаг ставится только на позднюю запись, переплата=её стоимость. Международный дорогой звонок: номер начинается с + и не с +996, duration_sec>0, стоимость минуты cost_som*60/duration_sec >20; переплата=max(0,cost_som−20*duration_sec/60). Локальные номера допустимы с +996 или 996. Сортировка для поиска дублей — по времени, независимо от порядка CSV. На каждое правило отдельная аномалия. В anomalies.json поля datetime,type,reason обязательны, amount_som рекомендуется для сверки суммы. Дополнительное anomaly_type — night_charge/new_subscription/duplicate_charge/international_rate/day_spike — облегчает автоматическую сверку, но не обязательно. reasons проверяются по смыслу. Если одно списание нарушает несколько правил, суммы в разных аномалиях нельзя суммировать как независимые потери. В этих наборах каждое инъецированное списание относится к одному типу, day_spike может агрегировать расходы других правил.

## 5. FAQ
FAQ содержит 15 стабильных ID. Ответы и коммерческие сведения учебные, брать их из faq.json. Базовый язык смешанной фразы определяется языком грамматической основы, бренд/русский термин не меняет кыргызскую основу. Для вопроса вне FAQ ожидаются faq_id=null и отказ от выдумывания ответа; язык всё равно ru/ky. Для низкой уверенности порог выбирает команда на открытом наборе. confidence ∈ [0,1], не обязан совпадать с эталонным числом. Пустой вопрос: ru, faq_id=null. Для оценки top-3 можно дополнительно вернуть candidates — список до 3 faq_id. Первое место равно faq_id. Контекстные диалоги проверяются отдельно в одном chat_id, между диалогами контекст сбрасывается; answer(text) без контекста не обязан угадывать предыдущую тему. /stats не раскрывает чужие персональные данные.

## 6. OTP
Телефон — строка 12 цифр с 996. verify.code — строка ровно из 6 цифр, ведущие нули сохраняются. Некорректный JSON/формат →400, отсутствие активного кода, неверный код, повторное использование →401. После elapsed >=120 s неиспользованный активный код →410. После 5 неверных кодов, относящихся к активному OTP, пятый ответ уже 423; блокировка действует [t,t+900). Верный код в блокировке тоже 423. send при блокировке →423. Несуществующий/истёкший код и ошибка формата не увеличивают счётчик 5 ошибок, но любой verify учитывается в IP-лимите. Код 000000 допустим. Одинаковая случайная строка нового и предыдущего OTP допускается генератором; в сценариях замены используется контролируемый тестовый источник с разными кодами.
Успешные send в скользящем окне (t−600,t] нумеруются 1,2,3. Между первым и вторым выдержать 30 s, вторым и третьим 60 s; после третьего действует задержка 120 s, но четвёртый всё равно запрещён, пока в окне 3 выдачи. Фактический отказ send не аннулирует действующий OTP. После полного очищения окна ступень сбрасывается. IP-лимит verify: 20 запросов в (t−60,t], 21-й →429; IP-лимит проверяется до проверки кода и блокировки номера. Успешная verify атомарно погашает код; одновременно успешен ровно один запрос. IP берётся из соединения либо доверенной тестовой конфигурации, не из произвольного X-Forwarded-For.
Доставка кода в тестовый перехватчик разрешена для испытаний. Доставка «SMS» для испытаний: сервис дописывает каждую выдачу одной строкой JSON `{"ts": "2026-11-21T09:00:00+06:00", "msisdn": "996770730000", "code": "012345"}` в файл `outbox/sms.jsonl` в корне репозитория (путь можно переопределить переменной окружения `OTP_OUTBOX`). Это имитация SMS-шлюза, а не хранилище сервиса: сервис этот файл не читает. capture_delivery в сценариях жюри — последняя строка этого файла для номера. Журнал безопасности и постоянное хранилище не должны содержать открытый код. Не добавляйте публичный HTTP-метод получения кода ради проверки. В тестах можно подменить часы и доставку или прогонять вручную с реальным ожиданием.

## 7. Покрытие
bounds.json задаёт прямоугольник с включёнными границами и сетку. Квадраты 200×200 м строятся в локальной равнопромежуточной модели: R=6371000, x=R*cos(lat0)*rad(lon−lon0), y=R*rad(lat−lat0); cell=(floor(x/200),floor(y/200)). cell_id = X{ix:03d}_Y{iy:03d}. Это локальная сетка задания, не Web Mercator. Центр (ix+0.5,iy+0.5)*200 преобразуется обратно в lat/lon. Измерения на максимальной границе включаются по правилу floor без отдельного ограничения индекса.
Сначала проверить обязательные поля, конечность чисел, timestamp ISO 8601 и географические границы, затем дедупликация по четырём нормализованным полям lat,lon,rsrp_dbm,timestamp (числа как числа). dropped_rows включает каждую отброшенную строку, в том числе пустую. Медиана по оставшимся, минимум 5 замеров на клетку. worst_cells сортировать по rsrp_median, затем cell_id, вернуть первые 3 объекта {cell_id,rsrp_median}. Красные median<−105. Для допустимой площадки расстояние до КАЖДОЙ существующей БС >=500 m. Покрытие: расстояние от площадки до центра красной клетки <=1000 m, гаверсинус R=6371000. Перебрать все пары допустимых площадок, максимизировать размер объединения; при равенстве выбрать лексикографически минимальную отсортированную пару ID. best_candidates — 2 ID, covered_weak_cells — размер объединения, а не сумма покрытий по отдельности.
